# prove — the proof workflow (`--type prove`, alias `disprove`)

For a stated claim that needs an answer with teeth: this pipeline fixes the claim precisely, gathers evidence for it, then dispatches a pass whose only job is to try to refute it, and emits a verdict backed by anchored evidence. The router hands this file the run's already-resolved axes — `explore` depth, the rigor profile, `against`, `ship`, and the row's `branch:` prefix where one exists — plus the claim (inline text, or resolved via an anchor) per stage 3 below; this file's job starts after resolution. The alternate invocation name is a pure alias, never a mode: the run is symmetric and the verdict follows the evidence gathered, never which name the user typed — treating it as an instruction to go find the refutation would bias the outcome, the same Goodhart failure this project's structural anti-cheating stance exists to prevent. For example: `dae prove --against <anchor>` and `dae disprove --against <anchor>` launch the identical run — this is the only other place either name appears in this file, as an axis value the router already resolved before this file loads, not as a branch here.

## Stages

**1. Setup, branching on `ship`.**
- **`ship: chat`** — Setup is skipped entirely, and with it everything it drags in: no `workflow-setup.sh`, no branch, no parent worktree, no run dir, no progress log, no docs-target resolution, no publish seam. Invoke `resolve-scratch.sh --slug <slug>` and take the path from its `SCRATCHDIR:` line rather than assembling it — the script creates the dir; there is no separate `mkdir -p`. State the resolved path to the user in chat. `resolve-scratch.sh` owns the resolution ladder and the variable name (see `artifact-locations`); neither is restated here.
- **`ship: publish`** — the router's shared Setup stage, on the row's `docs/` prefix. Referenced, not restated.

**2. The snapshot, at `chat` + `rigor ≥ med`.** `report.md` established this mechanism on `main`, and it is **not optional here**: this pipeline defaults to `rigor: {explore: med}`, so a chat-mode run reaches the `chat`/`≥ med` cell **by default** — not only under a `--rigor` override. Independent verifiers disagree when the tree moves underneath them; that is corrosive for a report and fatal here, where the verdict rests on a disagreement being real rather than an artifact of a moving tree. No git repo means no snapshot: warn and proceed, never block. Point at `report.md`'s Setup section for the mechanics — the detached-worktree recipe, where it lives on disk, the cleanup-allowlist note — and do not restate any of them; they belong to `report.md` alone.

**3. Fix the claim.** Write the claim under test down verbatim, before gathering anything, once and for the rest of the run. An inline claim is quoted from the ask as given. `--against <anchor>` resolves via `resolve-anchor.sh` — point at it and at `SKILL.md`'s anchor-resolution paragraph; do not restate the resolution mechanics — and the anchor names the subject under test, while the claim is the specific proposition the user stated about that subject (in passing: an anchor may resolve to the `plan` kind for an arbitrary document; the label is cosmetic and this file does not rely on it). A claim that cannot be stated as a proposition with a truth value cannot be run through this pipeline: stop and bring it back to the user rather than guessing one on their behalf.

**4. Gather (the collector).** Invoke the `explore` skill via the Skill tool at the resolved depth, output path in the scratch dir (`chat`) or the run dir (`publish`) — carry the map's PATH forward into the next stage, never its content. At `rigor: low`, invoke it directly; this is never `committee(explore, n=1)` — a `low` run produces no `committees/` directory. At `rigor ≥ med`, wrap it in the `committee` agent at the tier's width; point at `committee.md` for the member-file layout and consolidation mechanics, and restate none of it.

**5. Falsify.** This is the stage that makes the proof pipeline different from the report pipeline, and it runs **at every rigor tier, unconditionally** — a structural property of the pipeline, the falsification pass is dispatched, full stop, never an instruction to the model to try hard to refute the claim. A cold pass — one that has not seen the gathering pass's reasoning, only the fixed claim (stage 3) and the evidence paths (stage 4) — is asked to refute the claim, defaulting to "refuted" under uncertainty: an unresolved doubt never rounds up toward the claim holding. This is the same structural anti-cheating principle the builder's blind `contract-tester` embodies (point at `AGENTS.md`'s carried-invariants / review-rules section by name; do not restate the `contract-tester`'s mechanics here) — the agent that argued for the claim must not be the one that judges it. At `rigor: low` this is one cold pass. At `rigor ≥ med` the falsification pass is the committee's, at the tier's width, with members given differing lenses rather than repeats of the same prompt — point at `committee.md` for the fan-out/consolidation mechanics.

**6. Verdict + write.** Fill `proof-skeleton.md` — point at it by name for the frame and its section rules; do not re-list them here. Written to disk in **both** ship modes.

**7. Deliver (`chat`)** — the verdict and the proof document, in chat, in full, then state the scratch path, then **STOP**: no Record, no Ship, no PR gate, no `push-pr`, no `cleanup-merged`. The observable property, in `report.md`'s current wording: no branch, no commit, nothing staged, and nothing that reaches the product branch — a gitignored scratch-dir write and the stage-2 snapshot are permitted by construction.

**8. Record + Ship (`publish`)** — invoke `document-local` always; there is no mode branch and no document-skill dispatch here. It records the proof under the resolved docs root's `proofs/` subdirectory, `<docs-root>/proofs/<slug>-MM-DD-YY.md`, stated in terms of the **resolved** root — never hardcode `/docs`. Publishing beyond the repo is a CI job on merge, never a step of this run — point at `doc-format`. The draft PR opens at the record commit, for the same reason as `document.md` and `report.md`: no planner and no builders means nothing is committable before Record — reference the shared **Open the draft PR** step by name, restate nothing. **PR-gate spec of record:** the claim as fixed at stage 3, plus the proof document. **Scope boundary: nothing outside `<docs-root>/proofs/` may have changed.**

## Notes

- A proof run never writes source; if establishing the claim would require changing code, stop and recommend a build or diagnose run (mirrors `report.md` and `document.md`'s equivalent note).
- Read-only in both ship modes: the only files a proof run writes are its own proof document, the explore map, and the committee artifacts.
